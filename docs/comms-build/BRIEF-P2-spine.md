## Build (server/spine/)
1. `request-run.ts` — `requestRun(conversationId, trigger, opts)`: debounce (reuse the `nextTriageAt` lease + `claimTriageTurn` CAS from comms-sweep.ts; move them here and re-export so comms-sweep keeps compiling) and enqueue; `runDue(limit)` executes due runs (gated by `isCommsWorker()`). Wire the three entry points behind the `spine.enabled` flag: `comms-lanes.scheduleInboundTriage`, `comms-sweep.tickDueTriage`, and Ops Manager\x27s `run_comms_agent` tool (it may only call `requestRun`; remove its direct `runCommsAgent` import). When the flag is off, behaviour is byte-for-byte legacy.
2. `case-file.ts` — `buildCaseFile(conversationId)` per `CaseFile`: merged timeline (messages + calls with transcripts, quarantined excluded), media (reuse server/agents/media-context.ts for image blocks; video descriptions null until Phase 4), window state (reuse canSendFreeform/template logic), client (service_clients), live quote (reuse server/agents/quote-context.ts), open promises (promise-tracker), open flags (agent_questions with due_at), tags/stage, last run (agent_runs). `hash` = sha256 of the stable-serialised file. Persist the serialised file under `server/storage/case-files/<hash>.json` (gitignored) and return it; `agent_runs.case_file_ref` stores the hash.
3. `triage.ts` — `triage(caseFile)`: deterministic first (opt-out, spam patterns from first-contact-ack.ts, first-contact detection, keyword lexicons for money/date/complaint/callback from the replay script scripts/_comms-desk-replay.ts), then ONE schema-validated Claude call on `claude-haiku-4-5` via `server/llm.ts` (zod schema of TriageResult; on parse failure fall back to the rules result with source \x27rules\x27 and reasons[] noting it). Non-UK numbers are NOT dropped (decided 2 Sep). Any exception → lane \x27ben\x27. Writes tags/stage on the conversation (the autonomous tier) and an agent_runs row (agent \x27triage\x27) via the runner/ledger from Phase 1.
4. `packs.ts` + `packs/*.ts` — the packs from §3.4 as typed config: `customer.default`, `customer.post_quote`, `customer.exception`, `rules.first_contact`, `rules.followup`, `contractor.default`, `internal.ben`. `resolvePack(caseFile, triage)`. Tiers at launch per §3.4 (rules SEND; scoper intents DRAFT; contractor DRAFT). Money and dates must not exist as intents anywhere.
5. `guards.ts` — `checkProposal(proposal, pack, caseFile)`: bridge to `draft-guards.ts` detectors by GuardName; returns GuardVerdict; `escalate` mirrors ESCALATE_CODES from comms.ts.
6. `decide.ts` — `decide(...)` per §3.6: send iff tier SEND for the intent in this pack AND no open exception AND hours allow (reactive 24/7 within 45 min of an inbound, proactive only proactiveFromHour–proactiveToHour via server/working-hours.ts) AND deliverable; else pending with due_at; exceptions → flag with due_at; opted-out/spam → drop.
7. `exit.ts` — `exit(run)`: SEND → `queueDraft` + `approveAndSendDraft(id, approver, runId)`; PENDING → `queueDraft` with due_at + run_id; FLAG → agent_questions row (status flagged, due_at, run_id) + Pushover once; DROP/NONE → ledger event only. Everything writes ledger events with run_id.
8. `index.ts` — `runOnce(conversationId, trigger, agents: Record<AgentName, SpineAgent>)` orchestrating the chain and persisting a SpineRun to agent_runs (cost, usage, guards_hit, decision). Register a placeholder `rules` agent that returns null (rules-layer sends stay in server/rules-layer.ts) and accept the Scoper/Quote clerk/Recovery agents from the other panes via a registry (`registerAgent`).
