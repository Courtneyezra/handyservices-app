Run the estimator with `maxTokens: 16000` (runner opts), and make the belt cheaper to speak: `submit_build` accepts a compact shape (no procedure prose longer than 2 sentences per line, materials ≤ 8 per line, reasoning ≤ 200 chars), and the system prompt tells it so. If the runner still returns `max_tokens`, retry ONCE with an explicit "submit now with what you have, compactly" turn before failing.
2. **Single flight.** Exactly one estimator run per intake run: claim before dispatch (insert the `quote_estimates` row with status `running` keyed on `intake_run_id` and refuse a second when a non-superseded row exists for that intake; add a partial unique index `(intake_run_id) WHERE superseded_at IS NULL` via an idempotent migration). Find why two started (likely both the inline chain in index.ts AND the registry/lane dispatch picking the estimator up via `accepts`); keep one path and make the other a no-op.
3. **Failure still produces the draft.** When the estimator fails or times out, Route A must still create the draft from the clerk's intake using the pricing bridge's per-line fallback (reference rate × default duration, `check_this: true`, reason "estimator failed: <err>") so Ben always has something to price; the Pushover says "priced from reference rates, estimator failed". Status on the estimate row stays `failed` with the error.
4. Tests with fakes: max_tokens retry path, single-flight refusal, failure → fallback draft.
